# Reading IIO attribute names

Generated by `iio-tools/iio_explain.py --glossary`. Everything marked **[abi]** is true of every IIO device, not just the M2K.

## The one rule that matters

A `_raw` value is not a measurement. It is a count. To get a real number:

```
real value = (raw + offset) * scale
```

Offset is added **before** scale, not after. Offset is in raw counts; scale converts counts into the channel's unit.

## The units are not the ones you expect

| `count` | a count of events | no unit |

## How an attribute name is built

```
{in|out}_{type}{index}[_{modifier}]_{info}
```

| Part | Example | Means |
| --- | --- | --- |
| direction | `in_` | into the device (a measurement) |
| direction | `out_` | out of the device (a generator) |
| type | `voltage` | what is being measured |
| index | `0` | which channel |
| modifier | `_red` | narrows it further |
| info | `_raw` | what role this file plays |

A dash means a differential pair: `in_voltage0-voltage1_raw` is the difference between two pins, not either one against ground.

## Info words

| Info word | Its own unit | Means |
| --- | --- | --- |
| `calibbias` | counts | A calibration offset the driver applies on top of offset. |
| `calibscale` | dimensionless multiplier | A calibration gain the driver applies on top of scale. |
| `current_timestamp_clock` | text | Which kernel clock the timestamp channel reads. |
| `data_available` | bytes | How much captured data is waiting to be read. |
| `direct_reg_access` | hexadecimal register value | Raw read/write access to the chip's registers, exposed for debugging. |
| `en` | boolean -- 1 means enabled | Whether this channel is included in the streaming buffer. |
| `enable` | boolean | Starts and stops the streaming buffer. |
| `filter_high_pass_3db_frequency` | hertz | Corner frequency of a high-pass filter in the signal path. |
| `filter_low_pass_3db_frequency` | hertz | Corner frequency of a low-pass filter in the signal path. |
| `frequency` | hertz | The output frequency of a generator channel. |
| `hardwaregain` | decibels | A gain stage in the analogue path, in dB. |
| `index` | no unit -- a position | Where this channel's sample sits inside each buffer record. |
| `input` | the channel's unit | The converted value, already in the channel's units. No arithmetic needed. |
| `integration_time` | seconds | How long the sensor accumulates before producing a reading. |
| `label` | text | A human-readable name the driver or device tree gives this channel. |
| `length` | samples | How many samples the kernel buffer holds. |
| `length_align_bytes` | bytes | The alignment a buffer read must satisfy. |
| `mean_raw` | no unit -- a count | A mean of the raw samples, on the same scale as _raw. Apply offset and scale exactly as you would to _raw. |
| `offset` | counts | Added to the raw value BEFORE scale is applied. |
| `oversampling_ratio` | no unit -- a ratio | How many hardware samples get combined into one sample you receive. |
| `peak_raw` | no unit -- a count | A peak of the raw samples, on the same scale as _raw. Apply offset and scale exactly as you would to _raw. |
| `phase` | radians | The phase of a generator channel. |
| `powerdown` | boolean -- 1 means powered down | Turns the channel or stage off. 1 is off, not on. |
| `powerdown_mode` | text | Which powerdown behaviour to use. |
| `raw` | no unit -- a count | The unconverted number the converter produced. This is not a measurement yet. |
| `rms_raw` | no unit -- a count | A root-mean-square of the raw samples, on the same scale as _raw. Apply offset and scale exactly as you would to _raw. |
| `sampling_frequency` | hertz | How many samples per second this device or channel produces. |
| `scale` | the channel's unit per count | The multiplier that turns raw counts into real units. |
| `trigger` | text | Which trigger drives sampling on this device. |
| `type` | text -- a format string | The bit layout of each sample, e.g. le:s12/16>>0. |
| `watermark` | samples | How many samples must be ready before a read returns. |

## What `voltage0` actually is

Nothing in libiio says which pin a channel is wired to. Ask these in order:

1. **The channel name.** `iio_channel_get_name()` returns the driver's own name for the channel. Most drivers leave it empty; when it is set, believe it.
2. **The `label` attribute.** Same idea, settable from the device tree.
3. **The vendor library.** For the M2K, libm2k's `M2kAnalogIn` indexes `m2k-adc` channels directly as scope channels 1 and 2.
4. **The convention.** The kernel docs say an indexed channel corresponds to an externally available input, and that a driver should use a *named* channel when it does not. A strong hint, not a promise.

## Where to look it up yourself

- `Documentation/ABI/testing/sysfs-bus-iio` in the Linux source — the definitive description of every generic attribute. `./iio-tools/iio_abi_fetch.py --show in_voltage0_raw` prints it.
- The driver's `iio_chan_spec` table — says which index is which input.
- For the M2K: the libm2k source, which is what Scopy itself uses.
- The datasheet, for anything the software cannot know.
